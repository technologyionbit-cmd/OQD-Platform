# Aqd Backend

**Phase 1 — Infrastructure + Authentication.** NestJS/TypeScript, PostgreSQL
via Prisma. Implements the full auth API the Flutter app's `AuthRepository`
programs against (register/login/refresh/logout/me, password reset via OTP,
change-password, active-session management). See
`docs/backend/02-auth-and-authorization.md` for the contract and
`docs/backend/16-backend-roadmap.md` for later phases.

## Prerequisites

- Node.js ≥ 20 (developed against Node 24+)
- A local PostgreSQL server (any 14+; developed against 18)
- npm

Redis and Docker are **not** required for this phase. Rate limiting uses an
in-memory store; a distributed store is only introduced when the API runs on
more than one instance (see `docs/backend/14-security.md`).

## 1. Create the database

Against your local PostgreSQL superuser, once:

```sql
CREATE ROLE aqd LOGIN PASSWORD 'aqd_dev_password';
CREATE DATABASE aqd_dev OWNER aqd;
\c aqd_dev
CREATE EXTENSION IF NOT EXISTS citext;
```

Adjust the credentials to taste and mirror them in `DATABASE_URL` below.

## 2. Configure environment

```bash
cp .env.example .env
```

Then set a real `JWT_ACCESS_SECRET` (the file shows the one-liner) and make
`DATABASE_URL` match step 1. Never commit `.env`.

## 3. Install dependencies

```bash
npm install
```

If npm reports blocked install scripts, approve the first-party ones:

```bash
npm approve-scripts prisma @prisma/client @prisma/engines
npm install
```

## 4. Prisma

```bash
npm run prisma:generate   # generate the Prisma client
npm run prisma:deploy     # apply migrations to the database from step 1
```

`prisma/schema.prisma` defines the Phase 1 identity/organization foundation
(`users`, `refresh_tokens`, `verification_codes`,
`lawyer_registration_details`, `organizations`, `organization_members`,
`organization_invitations`). No other domain tables exist yet.

## 5. Run the app

```bash
npm run dev
```

Listens on `PORT` (default `3000`) with global prefix `/v1`.

Production: `npm run build && npm run start:prod` (runs `dist/src/main.js`).
Behind a reverse proxy, set `TRUST_PROXY` (hop count or proxy addresses —
see `.env.example`) or every user shares one rate-limit bucket.

## API docs (OpenAPI)

With the app running: interactive docs at `http://localhost:3000/v1/docs`,
raw spec at `/v1/docs-json`. On by default outside production; toggle with
`API_DOCS_ENABLED`. DTO schemas are generated by the `@nestjs/swagger` CLI
plugin (`nest-cli.json`) from the class-validator decorators, so they stay in
sync with validation automatically.

## 6. Health check

```
GET /v1/health
```

Returns `200` with `status: "ok"` when PostgreSQL is reachable, `503` otherwise.

## Auth API (all under `/v1/auth`)

| Method & path | Auth | Purpose |
|---|---|---|
| `POST /register` | — | Register (`accountType`: `individual` \| `company` \| `lawyer`) → `{ user, tokens }` |
| `POST /login` | — | `{ email, password }` → `{ user, tokens }` |
| `POST /refresh` | — | `{ refreshToken }` → `{ tokens }` (rotates; reuse ⇒ family revoked) |
| `POST /logout` | — | `{ refreshToken }` → 204 |
| `GET /me` | Bearer | Current user |
| `PATCH /me` | Bearer | `{ fullName, email }` → updated user |
| `POST /password/forgot` | — | `{ email }` → 204 (always; anti-enumeration), 429 over the per-address send limit |
| `POST /password/verify-otp` | — | `{ email, code }` → 204, or 422 `INVALID_VERIFICATION_CODE` / `VERIFICATION_CODE_LOCKED` |
| `POST /password/reset` | — | `{ email, code, newPassword }` → 204 (marks the email verified, revokes all sessions) |
| `POST /password/change` | Bearer | `{ currentPassword, newPassword }` → 204 (revokes other sessions) |
| `GET /sessions` | Bearer | Active sessions with a `current` flag |
| `DELETE /sessions/:id` | Bearer | Revoke one session |
| `DELETE /sessions` | Bearer | Revoke every session except the caller's |

- Access token: JWT, `JWT_ACCESS_TTL` (default 15m), carries `sub`/`role`/`sid`.
- Refresh token: opaque, 30 days, only its SHA-256 hash is stored.
- No email/SMS provider is wired — OTP codes are written to the server log
  (dev only). Swapping in a provider is confined to `OtpService.deliver`.
