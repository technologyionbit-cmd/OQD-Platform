# خطة عقد الكاملة — من هلأ لحد الإطلاق

## طريقة الاستخدام

- هاد الملف هو التراكر الرئيسي. أي محادثة جديدة: اقرأه، وشوف أول خطوة حالتها مش `Done`، واشتغل عليها بس.
- الشغل صفحة صفحة، full-stack: Flutter + NestJS + عقد الـ API + الأمان + الاختبارات.
- كل خطوة بتخلص، المستخدم بيراجعها ويتأكد منها، بعدها بنعلّمها `Done` وبنروح عالي بعدها.
- أي انحراف عن الخطة بينكتب تحت "ملاحظات تنفيذ" بآخر الملف.
- الخطة القديمة [individual-user-rollout.md](individual-user-rollout.md) والمرجع التقني [docs/backend/](../backend/) لسا مرجع للتفاصيل.

## الوضع عند بداية الخطة (2026-10-08)

- مربوط على backend حقيقي: auth، المحامين، الاستشارات والحجز، غرفة الاستشارة (state بس، بدون صوت/فيديو حقيقي)، العقود، الإجراءات الحكومية، الإشعارات، توثيق المحامي.
- لسا mock: الرسائل، الذكاء الاصطناعي، المستندات، الدفع والاشتراكات، الشركة والفريق، التوقيع المحفوظ.
- مراجَع بمعاييرنا: الصفحات 1–7 (Splash لحد لوحة المحامي والإشعارات والتوثيق) وتسجيل الدخول بالهاتف مع أكواد SMS.

## ملاحظات تنفيذ

- 0.2: كان الـ lock ناقصه `@emnapi/core` و `@emnapi/runtime` المتداخلين تحت `@unrs/resolver-binding-wasm32-wasi`، ومثبّت `@emnapi/wasi-threads@1.2.1` بدل `1.2.3`، فـ `npm ci` كان يرفض. انحلت بـ `npm install --package-lock-only`. بعدها npm الأحدث على السيرفر (11.19.0) طلب كمان `@emnapi/core@1.11.3` و `@emnapi/runtime@1.11.3` على المستوى الأعلى (peer deps)، و npm 11.6.2 تبعنا ما بيكتبهم. الحل: توليد الـ lock بـ `npx npm@12.2.0 install --package-lock-only`. الـ lock الناتج بيشتغل مع npm 11.6.2 و 11.19.0 و 12.2.0. **أي تعديل جاي على الـ lock لازم ينعمل بـ `npx npm@12.2.0` (أو npm محلي أحدث من 11.19).**
- 0.2 (إضافة): `npm audit fix` بدون `--force` رقّع ثغرة critical بـ `proxy-addr` (تزوير IP عبر IPv6، بتأثر على `TRUST_PROXY` و rate limiting)، وثغرات moderate بـ `multer` و `joi`. ضايل ثغرتين moderate بـ `js-yaml` عن طريق `@nestjs/swagger`، حلها بدّه swagger 12 (breaking). منأجلها لأنه Swagger لازم ينقفل بالـ production أصلاً (9.2).
- 0.3: الفحص كان يضغط على يوم بكرا ويتوقع موعد فاضي، بس الـ mock ما بيولّد مواعيد الجمعة والسبت، فكان يفشل كل خميس وجمعة. صار الفحص يضيف موعد فاضي لليوم بنفسه. الشاشة ما فيها مشكلة. ملاحظة: أول فحصين بالملف معتمدين على `cons_seed_1` (بعد 20 دقيقة من الآن)، فممكن يفشلوا إذا انشغلوا بين 23:40 و 00:00. منتعامل معهم لما نراجع الشاشة بالخطوة 3.2.
- على السيرفر استخدم `npm ci` العادي (مع dev)، لأنه `prisma` CLI موجود بـ devDependencies ومطلوب لـ `prisma migrate deploy`.
